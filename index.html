When you need an action, not an answer.
Use a decision model to turn messy evidence into a bounded choice, score, or gate. An incident report is free-form text; your workflow needs an owner, a severity level, and a decision about human escalation, not a paragraph to interpret.
You supply the evidence, allowed outcomes, and judgment criteria. Microsoft-Decision-1 returns typed numerical decisions your application can use directly. The Decision definition tab shows these inference-time criteria; they do not change the model's weights.

What that means in this demo.
The model interprets the incident and scores ownership, severity, and escalation. The application routes only when the selected owner's probability meets your threshold. Ambiguous or low-confidence cases go to human review. Changing a threshold needs no model call; changing the business rubric changes the next request's criteria, not the deployed model.

      
Choose the right tool.
Use ordinary rules when structured inputs already determine the action unambiguously. Use a generative LLM for explanations, summaries, drafts, or open-ended reasoning. Combine them when useful: decide first, then generate content if needed.
Decision-1 does not write explanations. This dashboard shows model outputs and application policy, never an invented model rationale. A structured-output LLM can also return valid labels, but this demo's chat baseline does not expose native option probabilities. Probabilities are not guarantees of correctness or production calibration; validate criteria and thresholds on representative labeled data before enabling consequential actions.
